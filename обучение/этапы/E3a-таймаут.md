# E3a. Таймаут ≠ отказ (только Seller A)

**Задачи:** T3a.1–T3a.3 · **~2.5 ч** · [S6](../сценарии.md#s6-таймаут-но-код-выдан)

## Зачем это учим

Самая дорогая ошибка интеграций: «не ответил за 2 секунды» = «не выдал». У селлера код уже списан. Если бы здесь уже был B, ИИ почти наверняка ушёл бы в fallback и спрятал баг вторым ключом.

## Сущности и значения

| Что вводим | Смысл | Дефолт | Где пригодится |
| --- | --- | --- | --- |
| `PUT /admin/faults` | воспроизводимые сбои | S6: timeoutRate=1, timeoutSeconds=**10** | S7/S8 сменят на errorRate |
| timeout клиента Shop | «неизвестно», не отказ | **2s** < 10s sleep | правило «не идём на B» |
| резерв code **до** sleep | иначе S6 не о чём | селлер списывает, потом висит | повтор с тем же request_id |
| retry на A | тот же `req_{orderId}:A` | | P7 новый GUID = второй ключ |

Seller B не добавляем. Три исхода вызова: успех / явный отказ / неизвестно.

## Что должно щёлкнуть

- Неизвестно → тот же request_id, тот же селлер.
- Нарисовать: timeout vs 503 vs 200.

## Сделать

faults API, идемпотентный `/issue` с резервом до sleep, HTTP timeout 2s, retry A, прогон S6.

## Проверить

S6: один code, в Kibana два issue с одним request_id. Payable один. Нет обращения к :8084 (порта ещё нет).
