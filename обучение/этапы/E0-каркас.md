# E0. Каркас Shop

**Задачи:** T0.1–T0.5 · **~2.5 ч** · [АРХИТЕКТУРА.md](../../АРХИТЕКТУРА.md) §3, §8

## Зачем это учим

Пока нет логов и одного живого сервиса, любой баг с деньгами — гадание. Сначала поднимаем **только магазин**: процесс Shop, база Postgres, логи в Kibana, проверка «жив ли сервис» с вашего компьютера.

Покупателя, банк, поставщиков и Grafana **сейчас не** поднимаем. Иначе непонятно, что сломалось: сеть, лог или ещё не написанная бизнес-логика.

## Простыми словами: что добавляем

| Что | Зачем простыми словами | Как у нас | Потом |
| --- | --- | --- | --- |
| Магазин на порту 8080 | Один процесс, с которым потом будут говорить все остальные | Shop.Api | все этапы |
| Postgres (с хоста порт 5433) | Единственная база магазина | пустая, без таблиц заказов | E1a — таблицы |
| В логе поле `service=shop` | В Kibana видно, чей это лог | Serilog → JSON | разбор любого инцидента |
| Elasticsearch ~1 GB памяти | Чтобы Docker на ноутбуке не умер | один узел, не «прод-кластер» | дашборды позже |

## Что должно стать ясно

- Отдельный контейнер ≠ «заглушка в том же процессе»: своя сеть, свой таймаут, свой лог.
- «Сервис отвечает 200 на /health» значит «процесс жив и дотянулся до своих зависимостей», а не «выдача ключей уже правильная».
- Без поля `service` логи из разных частей системы потом не разложить.

## Сделать

Solution: Shop.Domain / Infrastructure / Api.  
docker-compose: postgres + shop + Elasticsearch + Logstash + Kibana.  
`GET /health` на :8080. Логи в индекс вида `shop-*`. Описание запросов — в [Api docs](../../Api%20docs/API%20DOCS.md).

## Проверить

- Health магазина → 200.
- В Kibana после запроса есть документ с `service=shop`.
- `dotnet build` без ошибок. Тестов бизнес-логики ещё нет.

Сценарии покупки пока не прогоняем — только подготовка к цепочке логов.

## Разбор после прогона

| Вопрос | Ответ |
| --- | --- |
| Куда девается лог, если Elasticsearch ещё не готов? | Магазин ELK не ждёт. JSON уходит в очередь (до ~1000 строк); пока Logstash/ES лежат, лишнее **выбрасывается**. Процесс и `/health` живут. |
| Почему памяти ES ~1 GB, а не «как в проде»? | Один узел на ноутбуке. Кластер и десятки гигабайт здесь не нужны: логируем один Shop. |
| Чем потом health магазина будет отличаться от health поставщика? | Магазин: процесс + **своя** Postgres (заказы, деньги). Поставщик: свой запас кодов (своя база), без таблиц магазина. Оба — «жив и видит свои зависимости». |

Наблюдение с прогона:

```
2026-09-10: compose up — postgres/shop/logstash healthy, kibana available.
GET /health → 200 Healthy. Postgres stop → 503; start → снова 200.
ES индекс shop-*, документы с service=shop.
2026-09-11: Data View shop-* в Kibana; консоль docker — текст, в ELK — JSON.
Этап закрыт.
```

## Антипаттерн

Один контейнер «всё сразу» или сразу пять API «для полноты». Тогда сетевой таймаут поставщика не воспроизвести, а разбор превращается в кашу.
