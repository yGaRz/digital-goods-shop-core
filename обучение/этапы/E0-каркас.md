# E0. Каркас Shop

**Задачи:** T0.1–T0.5 · **~2.5 ч** · [АРХИТЕКТУРА.md](../../АРХИТЕКТУРА.md) §3, §8

## Зачем это учим

Платежный баг без логов — гадание. До бизнес-логики нужен **один** живой процесс: Shop, Postgres, JSON-логи в Kibana, запрос с хоста. Пять API сразу здесь не поднимаем: иначе не отличить «не собрался Buyer» от «упал вебхук».

## Сущности и значения этого этапа

| Что вводим | Смысл | Дефолт | Где пригодится |
| --- | --- | --- | --- |
| Shop.Api :8080 | оркестратор заказов и денег | health без БД-логики выдачи | все следующие этапы |
| PostgreSQL :5432 | единственная БД Shop | пустая, без таблиц заказов | E1a миграции |
| `service=shop` в логе | корреляция в Kibana | JSON Serilog | S14, любой инцидент |
| ES heap ~1 GB | чтобы Docker Desktop на ноуте жил | однонодовый | E5 дашборды, не кластер |

Buyer / Bank / Seller / Grafana / Prometheus — **не этот этап**.

## Что должно щёлкнуть

- Сервис в compose ≠ «заглушка в том же процессе»: сеть, таймаут, свой лог.
- Health — не бизнес; 200 на `/health` не значит, что выдача идемпотентна.
- Лог без `service` Logstash не съест как надо (P17).

## Сделать

Solution с Shop.Domain / Infrastructure / Api. docker-compose: postgres + shop + ES + Logstash + Kibana. `GET /health` :8080. Serilog → индекс `shop-*`. Postman env `shopUrl`.

## Проверить

- Postman: health shop 200.
- Kibana: документ после health или любого запроса, поле `service=shop`.
- `dotnet build` зелёный. Тестов бизнес-логики ещё нет.

Сценарии S: нет. Подготовка к S14.
