# E3b. Seller B и fallback

**Задачи:** T3b.1–T3b.3 · **~2.5 ч** · [S7](../сценарии.md#s7-fallback-a--b), [S8](../сценарии.md#s8-оба-селлера-недоступны), [S19](../сценарии.md#s19-один-code-в-пуле-a-и-b)

## Зачем это учим

B — запасной пул, не «ещё один retry A». Явный отказ A без выдачи → можно B со **своим** `req_{orderId}:B`. Timeout на A по-прежнему не повод звать B (это уже закрыли на E3a).

## Сущности и значения

| Что вводим | Смысл | Дефолт | Где пригодится |
| --- | --- | --- | --- |
| Seller B :8084 | тот же образ, другой контейнер | пул = хвост ключей ТЗ, не пересекается с A | S7, S8 |
| `request_id` `:B` | другая идемпотентность, другой пул | не тот же id что у A | иначе A и B «делят» выдачу |
| `delivery_failed` | оба явно отказали | восстановимый, HTTP GET 200 | E4a retry-stuck |
| seed без пересечения | один литерал code ≠ двум селлерам | | S19, UNIQUE в Shop |

## Что должно щёлкнуть

- S7: seller_id=B, A не держит ключ, один settlement.
- S8: не payable, не 500 клиенту.
- S19: такой seed должен быть невозможен.

## Сделать

Контейнер B, свой пул, правило fallback, S7/S8, защита пересечения пулов.
