# E4a. Сверка и дожим (малый объём)

**Задачи:** T4a.1–T4a.2 · **~2.5 ч** · [S10](../сценарии.md#s10-оплачен-не-выдан), [S11](../сценарии.md#s11-выдан-не-оплачен-должно-быть-0), [S12](../сценарии.md#s12-дожим-после-пополнения)

## Зачем это учим

«Оплатили, а ключа нет» должна находиться **запросом к API**, а не поиском по логам.  
Шторм рано: сначала сверка должна сходиться или честно врать на **одном** застрявшем заказе. Иначе 200 строк скроют ошибку в формуле.

## Простыми словами: что добавляем

| Что | Зачем простыми словами | Как у нас | Потом |
| --- | --- | --- | --- |
| Отчёт сверки | Операционная правда: сходятся ли статусы и деньги | `GET /admin/reconcile` | шторм глазами JSON / Grafana |
| «Оплачен, кода нет» | Список проблемных | деньги на удержании или «к возврату» | S10 |
| «Код есть, оплаты не было» | Так быть не должно — список пуст | | S11 |
| Кнопка дожима | Ещё раз попытаться выдать / разнести застрявшее | тот же номер запроса к поставщику | S12 |
| Из «к возврату» → долг поставщику + комиссия | После OOS удержание уже пусто | не списывать второй раз с пустого удержания | хвост после шторма |

Прогонять на 1–нескольких заказах (обрубить поставщика / маленький запас), не на 200.

## Что должно стать ясно

- Сверка статусов ≠ сверка денег. Формула: пришло от банка = удержание + долг поставщикам + комиссия + «к возврату».
- Дожим не трогает уже «выдан» и «оплата не удалась».

## Сделать

API сверки, API дожима, S10–S12 на малом объёме.

## Проверить

После S1 расхождение 0.  
S10 список не пуст, когда надо. S11 пуст.  
S12 после доливания ключей: «выдан» вырос, «к возврату» упал, повторный дожим безопасен.
