# E1a. Каталог и заказ «создан»

**Задачи:** T1a.1–T1a.4 · **~2 ч** · только Shop

## Зачем это учим

Заказ — это «человек хочет купить вот этот товар за вот эту цену». Цену **копируем в заказ** в момент создания: потом банк пришлёт свою сумму, и магазин сверит её с этой копией, а не с тем, что сейчас на витрине.

Пока банка нет: проверяем, что товары из задания есть, неизвестный товар не создаёт заказ, по номеру заказа можно его прочитать.

## Простыми словами: что добавляем

| Что | Зачем простыми словами | Как у нас | Потом |
| --- | --- | --- | --- |
| Таблица товаров | Витрина: 12 позиций из задания | `products`, seed | покупки; шторм возьмёт **другой** товар |
| Цена внутри заказа | Снимок «за сколько договорились» | `orders.amount` | сверка с суммой от банка |
| Статус «создан» | Ждём оплату, к поставщику ещё не ходим | `created` | ветки «оплачен» / «оплата не удалась» |
| Типы topup / key / … | В лабе логика одна: всем потом выдаём код | не ветвим | в записке можно сказать, что в проде topup был бы другим API |

Покупателя-сервиса ещё нет: заказ создаём руками через API docs / curl на Shop.

## Что должно стать ясно

- Список из задания — не картинки, а контракт: после seed ровно эти SKU.
- Два создания подряд без специального заголовка = **два** заказа. Это норма на этом этапе; защита от двойного клика — позже (E1d).

## Сделать

Миграции `products` + `orders`. Seed 12 SKU.  
`POST /orders`, `GET /orders/{id}`, список товаров.  
Тесты: успешное создание, неизвестный SKU, заказ не найден.

## Проверить

- 12 товаров в каталоге.
- Создание `STEAM-TOPUP-500` → статус `created`, сумма 500.
- Неизвестный sku → ошибка клиента (4xx), не 500.

## Разбор после прогона

| Вопрос | Ответ |
| --- | --- |
| Почему сумму копируем в заказ, а не каждый раз читаем цену с витрины? | Это снимок договорённости. Банк сверяется с `orders.amount`, а не с текущим прайсом. |
| Что сломается, если цену всегда брать из `products`? | Можно «переценить» заказ чужой суммой из уведомления банка или сменой прайса — учёт поедет. |
| Нужен ли уже заголовок от двойного клика? Чем два «создан» опасны, когда появится банк? | На E1a нет. С банком оба могут стать «оплачен» → два удержания на один клик. Защита — на E1d. |

Наблюдение:

```
2026-09-11: migrate + seed 12 SKU. GET /products = 12, STEAM-TOPUP-500.
POST /orders → 201 created amount=500. unknown sku → 404.
dotnet test: 5 passed. API docs: Catalog + Orders.
```

## Антипаттерн

Таблица заказов без суммы и sku («потом допишем»). Тогда сверять уведомление банка будет не с чем.
