# E1b. Buyer — один покупатель

**Задачи:** T1b.1–T1b.3 · **~1 ч**

## Зачем это учим

Buyer — тонкий клиент витрины: **ничего не хранит**. Деньги и ключи ему не принадлежат. Отделяем «человек нажал купить» от «магазин создал заказ», чтобы потом шторм и Postman били в один контракт.

## Сущности и значения

| Что вводим | Смысл | Дефолт | Где пригодится |
| --- | --- | --- | --- |
| Buyer.Api :8081 | оркестрация покупки | без БД | S1, S20, S9 |
| `POST /purchases { sku }` | один покупатель, один заказ | пока **без** `/storm` | `/storm` только на E4b, иначе перепрыгнем S20 |
| `service=buyer` | кусок цепочки логов | | S14: purchase → shop create |
| ссылки Buyer в API docs | `:8081` | | ручные прогоны S1/S20 |

## Что должно щёлкнуть

- Buyer упал — Shop и деньги целы.
- Один `purchases` = один `POST /orders`. Пока без идемпотентности — на E1d.

## Сделать

Проект Buyer, сервис в compose, health, прокси на Shop, лог с `service=buyer`, тест одной покупки.

## Проверить

- Health :8081.
- `POST /purchases` SKU `STEAM-TOPUP-500` → `orderId`, статус `created`.
- В Kibana два сервиса на один будущий order_id (buyer + shop), когда начнёте писать order_id в лог.

## Разбор после прогона

| Вопрос | Ответ |
| --- | --- |
| Почему у Buyer нет своей таблицы заказов? | Buyer — клик пользователя, не владелец денег/ключей. Источник правды — Shop `orders`. Дубликат таблицы = рассинхрон и «чья правда?» на ретраях. |
| Почему `/storm` не делаем «заодно» в этом же PR? | Шторм 200×30 — E4b после S20. Иначе пропускаем лестницу: один покупатель → несколько при полном остатке → дефицит. |
| Что должен прокинуть Buyer в Shop, чтобы S18 сработал позже? | `Idempotency-Key` на create (E1d). Сейчас один purchase = один order; двойной клик даст два `created`. |

Наблюдение:

```
2026-09-11: Buyer :8081, compose service + Shop__BaseUrl.
POST /purchases STEAM-TOPUP-500 → 201 orderId + created (прогон против живого Shop).
Health buyer → shop /health. Логи service=buyer + order_id; shop create с OrderId.
dotnet test: Shop 5 + Buyer 4. API DOCS: тела + ссылки Buyer.
docker build buyer: сбой bake из‑за кириллицы в пути репо — образ позже с хоста/короткого пути.
```
