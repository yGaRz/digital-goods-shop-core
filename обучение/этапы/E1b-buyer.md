# E1b. Buyer — один покупатель

**Задачи:** T1b.1–T1b.3 · **~1 ч**

## Зачем это учим

Buyer — тонкий клиент витрины: **ничего не хранит**. Деньги и ключи ему не принадлежат. Отделяем «человек нажал купить» от «магазин создал заказ», чтобы потом шторм и Postman били в один контракт.

## Сущности и значения

| Что вводим | Смысл | Дефолт | Где пригодится |
| --- | --- | --- | --- |
| Buyer.Api :8081 | оркестрация покупки | без БД | S1, S20, S9 |
| `POST /purchases { sku }` | один покупатель, один заказ | пока **без** `/storm` | `/storm` только на E4b, иначе перепрыгнем S20 |
| `service=buyer` | кусок цепочки логов | | S14: purchase → shop create |
| `buyerUrl` в Postman | | | коллекция E7 |

## Что должно щёлкнуть

- Buyer упал — Shop и деньги целы.
- Один `purchases` = один `POST /orders`. Пока без идемпотентности — на E1d.

## Сделать

Проект Buyer, сервис в compose, health, прокси на Shop, лог с `service=buyer`, тест одной покупки.

## Проверить

- Health :8081.
- `POST /purchases` SKU `STEAM-TOPUP-500` → `orderId`, статус `created`.
- В Kibana два сервиса на один будущий order_id (buyer + shop), когда начнёте писать order_id в лог.
