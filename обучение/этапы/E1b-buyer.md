# E1b. Buyer — один покупатель

**Задачи:** T1b.1–T1b.3 · **~1 ч**

## Зачем это учим

Buyer — тонкий «клиент нажал Купить»: **ничего своего не хранит** (ни денег, ни ключей, ни таблицы заказов).  
Отделяем «человек нажал» от «магазин создал заказ», чтобы потом и один покупатель, и шторм били в один и тот же контракт.

## Простыми словами: что добавляем

| Что | Зачем простыми словами | Как у нас | Потом |
| --- | --- | --- | --- |
| Сервис Buyer на :8081 | Принимает «купить sku», зовёт магазин | без своей БД | S1, несколько покупателей, шторм |
| `POST /purchases` | Одна покупка = один заказ в Shop | пока **без** массовой атаки `/storm` | `/storm` только на E4b |
| В логе `service=buyer` | Видно звено цепочки | Serilog | собрать путь покупки по логам |
| Ссылки в API docs | Ручные прогоны с хоста | `:8081` | сценарии |

## Что должно стать ясно

- Упал Buyer — магазин и деньги целы.
- Один `purchases` = один `POST /orders`. Защита от двойного клика — на E1d.

## Сделать

Проект Buyer, сервис в compose, health (магазин доступен), прокси на создание заказа, лог `service=buyer`, тест одной покупки, API docs.

## Проверить

- Health :8081 → 200.
- Покупка `STEAM-TOPUP-500` → номер заказа, статус `created`.
- В логах оба сервиса на один будущий номер заказа (buyer + shop).

## Разбор после прогона

| Вопрос | Ответ |
| --- | --- |
| Почему у Buyer нет своей таблицы заказов? | Buyer — клик. Правда про заказ — в магазине. Вторая таблица = рассинхрон. |
| Почему массовую атаку `/storm` не делаем «заодно»? | Шторм — после ступени «несколько покупателей, ключей хватает». Иначе перепрыгнем лестницу. |
| Что позже прокинуть в магазин против двойного клика? | Заголовок идемпотентности на create (E1d). Сейчас два клика = два заказа. |

Наблюдение:

```

POST /purchases STEAM-TOPUP-500 → 201 orderId + created.
Health buyer → shop /health. Логи service=buyer + order_id.
dotnet test: Shop + Buyer. API DOCS.
docker build buyer: сбой bake из‑за кириллицы в пути — образ с короткого пути.
```

## Антипаттерн

Buyer сам ходит в банк и к поставщику. Тогда гонки и деньги — каша в клиенте, а не в магазине.
