# E1. Заказ, эскроу, выдача

**Задачи:** T1.1–T1.6 · **~5 ч** · сценарии [S1](../сценарии.md#s1-happy-path), [S2](../сценарии.md#s2-оплата-не-прошла)

## Зачем это учим

Эквайринг говорит «деньги с карты сняты». Это **не** «селлер получил». Разница — эскроу. Без неё любая невыдача ключа превращает ledger в ложь.

## Что должно щёлкнуть

- `paid` = обязательство площадки перед клиентом (товар или возврат), не доход селлера.
- Settlement = проводка после **уникального** кода.
- `payment_failed` — финал без `/issue`.
- Вебхук должен ответить быстро (P14): долгий HTTP к селлеру внутри webhook — бомба для E2.

## Сделать

Миграции, seed 12 SKU, Buyer `purchases`, Bank `payments`, Shop FSM + эскроу + выдача через Seller A без faults, GET order, черновик reconcile.

## Проверить

Прогнать **S1** и **S2**. На S1 руками открыть три проводки заказа в `ledger_entries`. Назвать вслух счета debit/credit.

## Разобрать

- P2 settlement на вебхуке  
- P14 выдача в HTTP вебхука  
- P15 выдача до paid  
- P19 комиссия не в ledger
