# E6. Каталог под нагрузкой

**Задачи:** T6.1–T6.3 · **~3 ч** · [S15](../сценарии.md#s15-горячая-витрина-остатков)

## Зачем это учим

Не платежи, но соседний контур маркетплейса: витрина остатков не должна делать тяжёлый COUNT на каждый хит. Нужен план запроса, не «добавить Redis наугад».

## Сущности и значения

| Что вводим | Смысл | Дефолт | Где пригодится |
| --- | --- | --- | --- |
| ≥1000 SKU | нагрузка на «горячий» список | поверх 12 из ТЗ | EXPLAIN в записке |
| `GET /catalog/stock` | фиксированный доступ (in_stock, sort, limit), не dump | | |
| индекс / денорм. остаток | витрина не считает COUNT по ключам селлера каждый раз | выбрать одно, описать инвариант с выдачей | связь с S9: после шторма витрина не врёт |

12 учебных SKU остаются; тысячи — синтетика.

## Что должно щёлкнуть

- Горячий запрос = предикат + индекс.
- EXPLAIN — артефакт обучения.

## Сделать

Seed 1000+, endpoint, индекс(ы), текст EXPLAIN до/после.
