# E1d. Seller A — выдача и settlement

**Задачи:** T1d.1–T1d.5 · **~2.5 ч** · [S1](../сценарии.md#s1-happy-path), [S18](../сценарии.md#s18-повтор-создания-заказа)

## Зачем это учим

Ключ уникален. Деньги селлеру — **после** уникального кода, не на `paid`. Вебхук должен ответить быстро: `/issue` живёт в worker/outbox (P14), иначе E2 взорвётся ещё до «честной» гонки.

## Сущности и значения

| Что вводим | Смысл | Дефолт | Где пригодится |
| --- | --- | --- | --- |
| Seller A :8083 | пул сырых code | faults=0; голова пула ТЗ | S1, S20, 30 ключей шторма |
| `POST /issue` | выдать code по request_id | тот же request_id → тот же code | S6, даже если B ещё нет |
| `request_id=req_{orderId}:A` | стабильный ключ выдачи на A | не GUID на каждый retry | P7 |
| `outbox` + worker | выдача после коммита вебхука | с этого этапа, не «на E2» | S3, retry-stuck E4a |
| `platform_fee` 10% | отдельный счёт | 50 ₽ с 500 | бумага S9 с 1290 |
| `seller_payable:A` | долг селлеру | 450 после S1 | не путать с B на E3b |
| факт `orders.code` UNIQUE | один code — один заказ | | S19, S9 |
| `Idempotency-Key` create | двойной клик | | S18 vs S20 (там ключи разные) |

Seller B не поднимаем.

## Что должно щёлкнуть

- S1 вслух: debit/credit трёх фаз (эскроу, потом settlement).
- Source of truth пула — селлер; Shop хранит факт.
- Выдача только из `paid`/`delivering` (P15).
