## 1. Топология

Клиенты → Buyer → Shop → Seller A/B. Bank эмулирует эквайринг (вебхук). Shop владеет заказами, ключами площадки в ledger и сверкой. Селлер владеет пулом кодов. Банк денег внутри ledger не двигает — только событие `paid`/`failed`.

```
Postman
  ├─ Buyer.Api     :8081   POST /purchases, POST /storm
  ├─ Shop.Api      :8080   заказы, webhook, reconcile, retry, витрина
  ├─ Bank.Api      :8082   POST /payments, /burst, /batch
  ├─ Seller A      :8083   POST /issue, admin keys/faults
  └─ Seller B      :8084   то же, fallback
Shop ── PostgreSQL :5432
все сервисы ── Logstash :5000 ── Elasticsearch :9200 ── Kibana :5601
Shop (+sellers) ── Prometheus :9090 ── Grafana :3000
```

Деньги:

1. Вебхук `paid` → `BankAsset +X` / `Escrow +X`.
2. Уникальная выдача ключа → `Escrow −X` / `SellerPayable +(X−fee)` / `PlatformFee +fee`.
3. Нет ключа → `Escrow −X` / `RefundPending +X`. Селлеру ничего.

Списание клиенту / начисление селлеру — **settlement после выдачи**, не единственная проводка в момент вебхука.

Пустой остаток: статус `out_of_stock` или HTTP **409**, в логах Information, **не 500**.

## 2. Инварианты (после любой гонки)

1. `SUM(debit) = SUM(credit)` по `ledger_entries`.
2. Число `delivered` = число keys с `order_id`.
3. Один `code` — один заказ. Один `event_id` — одна обработка платежа.
4. `bank_captured = escrow + seller_payables + platform_fees + refund_pending`.
5. Нет `delivered` без `paid`. Нет двух кодов на один заказ.
6. 50 вебхуков на один заказ → одна выдача.
7. 200 покупок × 30 ключей → 30 `delivered`, остальные `out_of_stock`, без всплеска 5xx.

## 3. Каталоги и сервисы

```
src/Shop.Domain/
src/Shop.Infrastructure/
src/Shop.Api/
src/Buyer.Api/
src/Bank.Api/
src/Seller.Api/          # один образ, два контейнера
deploy/docker-compose.yml
deploy/elk/
deploy/grafana/
deploy/prometheus/
postman/
tests/
```

| Сервис | Владеет | Не владеет |
| --- | --- | --- |
| Shop | orders, payment_events, ledger, каталог/остатки для витрины, оркестрация выдачи | пул «сырых» ключей селлера до `/issue` |
| Buyer | ничего персистентного | деньги, ключи |
| Bank | генерация event_id, доставка вебхука | ledger |
| Seller A/B | свой пул code, идемпотентность request_id, faults | заказы магазина |

Worker доставки — hosted service в Shop.Api + `POST /admin/retry-stuck`.

### Shop REST

`POST /orders`, `GET /orders/{id}`, `POST /webhook/payment`, `GET /admin/reconcile`, `POST /admin/retry-stuck`, `GET /catalog/stock` (этап каталога), `GET /health`, `GET /metrics`.

FSM: `created → paid → delivering → delivered`; `payment_failed`; `out_of_stock` и `delivery_failed` восстановимые.

### Buyer REST

`POST /purchases { sku }`, `POST /storm { sku, count }`.

### Bank REST

Вебхук как в ТЗ (`event_id`, `order_id`, `status`, `amount`, `currency`, `created_at`).

`POST /payments`, `POST /payments/burst` (дубли одного event_id **и** разные event_id на один заказ), `POST /payments/batch` (шторм: список orderId).

### Seller REST

`POST /issue { request_id, sku, order_id }` — тот же `request_id` → тот же code.  
`POST /admin/keys/seed`, `PUT /admin/faults { errorRate, timeoutRate, timeoutSeconds }`, `GET /admin/keys/available`.

Таймаут ≠ отказ: код мог быть зарезервирован до обрыва ответа. Shop не вызывает B, если A «неизвестно» (timeout); retry A с тем же request_id. B — если A явный 5xx/отказ.

## 4. Данные (Postgres, владелец Shop)

- `products` — SKU ТЗ; на этапе каталога тысячи строк + индекс витрины остатков.
- `orders` — sku, amount, status, request_id, seller_id, code.
- `payment_events` — `event_id UNIQUE`, можно появиться **до** заказа.
- `keys` — `code UNIQUE`, `order_id UNIQUE NULL`; резерв `FOR UPDATE SKIP LOCKED`.
- `ledger_entries` — append-only, `idempotency_key UNIQUE`.
- `outbox` — выдача после коммита вебхука, worker читает.

Счета: `bank_asset`, `escrow`, `seller_payable:{id}`, `platform_fee`, `refund_pending`.

---

## 5. Наблюдаемость

- Serilog JSON → Logstash TCP → ES `shop-*` → Kibana (`service`, `order_id`, `event_id`, `request_id`, `reason`).
- Prometheus + Grafana: статусы заказов; `keys_available`; HTTP 2xx/409/5xx; `ledger_imbalance=0`.
- ES однонодовый, heap ~1 GB.
